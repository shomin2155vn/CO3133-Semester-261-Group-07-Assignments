Problem statement

Food-11 recognition is a supervised image-classification task: given one food photograph, predict its single supplied category. The study asks whether ImageNet-pretrained visual features and backbone fine-tuning improve recognition over a compact network trained from scratch, and how those choices affect class-wise errors and computational cost. Macro-F1 is the primary metric because it gives equal weight to all 11 categories.

The task is defined by the following elements:

  • Prediction unit: One RGB food photograph assigned to one broad category; there are no bounding boxes, segmentation masks, or ingredient-level labels.
  • Input: A float32 tensor x ∈ ℝ3×256×256. The notebook resizes the longer image side to 256 pixels with bilinear interpolation, centers the image on a black square canvas, and applies ImageNet RGB normalization.
  • Output: Eleven logits zθ(x) ∈ ℝ11, one for each Food-11 category (Bread, Dairy product, Dessert, Egg, Fried food, Meat, Noodles-Pasta, Rice, Seafood, Soup, and Vegetable-Fruit). The predicted label is the highest-scoring class after softmax; these scores are not assumed to be calibrated probabilities.
  • Objective and primary metric: Training minimizes unweighted multiclass cross-entropy in FP32. Held-out performance is assessed primarily with test Macro-F1, alongside accuracy, per-class metrics, confusion matrices, and runtime measures.
  • Main difficulties: Food appearance varies with preparation, viewpoint, lighting, scale, and background; some categories have overlapping visual cues, composite dishes have one broad label, and the source training counts are imbalanced (up to a 5.36:1 ratio).

The frozen-versus-full ResNet-18 comparison holds the architecture and ImageNet initialization fixed while changing whether the backbone is updated. Comparisons with SimpleCNN also change architecture and initialization, so they describe overall model differences rather than isolating a causal effect of pretraining alone.

Images were treated as duplicates when they shared the same MD5 hash or as near-duplicates when their pHash Hamming distance was at most 5. Both checks used the same removal logic: an image was removed only if a matching representative had already been retained. MD5 deduplication was performed first, followed by pHash deduplication. Each stage processed duplicates within partitions before removing duplicates across partitions, with retention priority given to training, then validation, and finally evaluation. Within each partition, the first eligible image in the existing order was retained. Two additional redundant images were removed after manual inspection, while their counterparts were retained. Label consistency was also checked to distinguish repeated images from identical images assigned to different categories, All images removed during deduplication shared the same class label as their retained counterparts. Dataset bias and limitations

  • Class imbalance. The largest classes in the original training split have about 5.36 times as many images as Rice. This motivates using Macro-F1 as the primary metric.
  • Broad and overlapping categories. Dishes within a class can look different, while dishes from different classes may share colors, textures, or preparation styles. A mixed plate can contain several types of food and still carry a single label.
  • Annotation ambiguity. Some sampled images contain distracting background subjects or off-topic content, such as a shop sign labeled Dessert. These examples suggest possible label noise, whose frequency across the dataset was not measured.
  • Photo-style bias. Some Dairy product and Vegetable/Fruit images use studio backgrounds, while other classes include restaurant photos. Models may use these background cues alongside the appearance of the food.
  • Duplicates and grouping metadata. Duplicate images require cleaning within and across the predefined splits. The dataset provides food-class labels but lacks subject, restaurant, plate, and scene identifiers for grouped splitting.

Data preprocessing

Data cleaning and annotation handling

All 16,643 original image files were successfully decoded as RGB JPEGs, with no empty or unreadable files. Exact duplicates, near-duplicates, and two manually identified redundant images were removed as described in the leakage-control protocol. Class labels are inherited from the dataset folders. Potentially ambiguous annotations are discussed as dataset limitations rather than automatically relabeled.

Resizing and padding

Each image is converted to RGB and resized using bilinear interpolation so that its longer side becomes 256 pixels while preserving its aspect ratio. The resized image is centered on a black 256 × 256 canvas, with padding divided as evenly as possible between opposite sides. This produces a uniform input size without cropping image content or distorting its proportions.

Normalization

Pixel values are converted to floating-point values on the [0, 1] scale and normalized independently for each RGB channel using the fixed ImageNet mean (0.485, 0.456, 0.406) and standard deviation (0.229, 0.224, 0.225). These constants match the normalization expected by the pretrained ResNet-18 weights. The same normalization is applied to SimpleCNN to keep input preprocessing consistent across configurations.

Data augmentation

Training images undergo random horizontal flipping with probability 0.5 after resizing and padding. No rotation or random cropping is applied. Horizontal flipping is disabled in the augmentation ablation. Validation and evaluation images use the same resizing, padding, and normalization steps without random augmentation.

Input tensor shapes

Each preprocessed image is represented as a float32 tensor of shape [3, 256, 256], corresponding to the RGB channels, height, and width. Each class label is an integer from 0 to 10.

Example batch after preprocessing

Training, validation, and evaluation use a batch size of 128. Training samples are shuffled, while validation and evaluation samples retain their order. A full batch has the shapes and data types below. The final batch may contain fewer images because incomplete batches are retained. 

images: shape [128, 3, 256, 256], dtype torch.float32

Training Behaviors

SimpleCNN

Training and validation performance remain relatively low and track each other closely. This pattern suggests incomplete fitting within the 25-epoch budget. Training loss is still improving late in training, and two seeds select the final epoch. The runs leave open how much of the remaining limitation comes from model capacity, optimization, or training duration. The selected checkpoints are at epochs 22, 25, and 25 for seeds 42, 43, and 44, respectively.

ResNet-18 frozen

Validation performance is broadly stable in the later epochs, suggesting limited additional gains from head-only training under the current protocol. The selected epochs for seeds 42, 43 and 44 are 22, 25 and 22, respectively.

ResNet-18 full fine-tuning

After its early minimum, validation loss broadly plateaus or rises while training loss continues to fall. This persistent gap is consistent with overfitting later in training, despite strong validation performance. The selected epochs for seeds 42, 43 and 44 are 14, 19 and 17, respectively.

Comparison and discussion

Overall predictive performance

Fully fine-tuned ResNet-18 achieved the highest mean test Macro-F1 at 91.67%, followed by frozen ResNet-18 at 85.26% and SimpleCNN at 57.58%. Top-1 accuracy followed the same ordering at 91.37%, 84.62%, and 60.40%, respectively. The model ranking therefore holds when weighting each test image equally for accuracy and each food class equally for Macro-F1.

Class-specific improvements and remaining errors

Rice showed the largest F1 improvement from SimpleCNN to frozen ResNet-18, rising from 43.00% to 92.39%. Egg showed the largest further improvement with full fine-tuning, rising from 79.13% to 91.20%. Dairy product remained the lowest-recall class at 80.50% for the fully fine-tuned model. The packaged-butter example in Figure 26 illustrates its recurring confusion with Dessert.

Architecture and input representation

All three models used the same 3 × 256 × 256 RGB inputs after aspect-ratio-preserving resizing, black padding, and ImageNet normalization. SimpleCNN learned its features from scratch. For each matched seed, both ResNet-18 variants started from the same ImageNet-pretrained backbone weights and the same initial classification head. The frozen model’s performance shows that the pretrained features already transfer to Food-11, and full fine-tuning yielded a further gain under the evaluated training settings.

Training behavior, loss, and prediction confidence

SimpleCNN continued to improve near the end of the 25-epoch budget, while frozen ResNet-18 largely plateaued. Full fine-tuning reached nearly perfect training accuracy and showed a persistent gap between training and validation accuracy. It also achieved the lowest mean test cross-entropy at 0.3197, compared with 0.4938 for frozen ResNet-18 and 1.2060 for SimpleCNN.

The fully fine-tuned model assigned a softmax score of 98.219% to Dessert for an image labeled Dairy product. A calibration analysis would measure how closely these scores correspond to observed accuracy across the test set.

Computational trade-offs

SimpleCNN was the smallest model and had the fastest measured inference at 0.81 ms per image. Frozen ResNet-18 trained only 5,643 parameters. Both ResNet-18 variants ran the full backbone during inference, averaging 2.66 ms per image for the frozen model and 2.48 ms per image for the fully fine-tuned model. Full fine-tuning took about 60.3 minutes per run including validation, compared with 49.5 minutes for frozen ResNet-18.

Hypothesis assessment and scope

Both pretrained ResNet-18 configurations outperformed SimpleCNN on the evaluated Food-11 split, supporting the study hypothesis. The comparison with SimpleCNN combines differences in architecture, capacity, initialization, and training policy. The comparison within ResNet-18 holds the architecture and initial weights fixed for each matched seed, supporting full fine-tuning under the tested settings. The results cover three training seeds on the same cleaned data partitions.

Limitations

Data limitations

Class imbalance. The largest classes in the original training split contain about 5.36 times as many images as Rice. Macro-F1 gives each class equal weight, while per-class scores for smaller classes are more sensitive to individual errors. The test set contains 90 Rice images and 440 Dessert images.

Broad and overlapping categories. Dishes from different classes can share colors, textures, and preparation styles. Food-11 assigns one label per image, so mixed dishes can make some errors difficult to interpret.

Annotation ambiguity. Some images contain off-topic content, such as a shop sign labeled Dessert. These examples suggest possible label noise, whose frequency across the dataset was not measured.

Photo-style bias. Some Dairy product and Vegetable/Fruit images have studio backgrounds. Models may use these background cues alongside the appearance of the food.

Duplicates and grouping metadata. Duplicate removal reduces overlap within and across the predefined splits. All three seeds use the same cleaned split, so they measure variation across training runs on that split. The dataset lacks subject, restaurant, plate, and scene identifiers for grouped splitting.

Method limitations

The comparison between SimpleCNN and pretrained ResNet-18 combines differences in architecture, parameter count, and initialization. The two ResNet-18 variants were compared under the selected learning rates and a fixed budget of 25 epochs. SimpleCNN’s training loss was still decreasing near epoch 25, so a longer run could change its results. The horizontal-flip ablation used three matched seeds, which limits how precisely the small gains can be estimated.

Generalization and future work

Evaluation on an independent food-image dataset would test whether the model ranking holds across image sources, cuisines, and presentation styles. Comparing randomly initialized and ImageNet-pretrained ResNet-18 under the same training settings would help isolate the effect of pretraining. Longer SimpleCNN runs with validation-based checkpoint selection would clarify the effect of the training budget. Reviewing Dairy product images predicted as Dessert would help identify which errors involve ambiguous labels or scenes.

Conclusion

Both pretrained ResNet-18 variants outperformed SimpleCNN on the evaluated Food-11 split, supporting the first hypothesis. Mean test Macro-F1 was 57.58% for SimpleCNN, 85.26% for frozen ResNet-18, and 91.67% for fully fine-tuned ResNet-18. The improvement from the frozen to the fully fine-tuned model supports updating the backbone under the tested training policy.

Horizontal flipping improved test Macro-F1 at all three seeds for both ResNet-18 variants, supporting the second hypothesis for those models. The mean paired changes were +0.41% for frozen ResNet-18 and +0.55% for full fine-tuning. The effect on SimpleCNN was inconclusive because its changes varied in direction across seeds. Fully fine-tuned ResNet-18 with horizontal flipping achieved the highest mean test Macro-F1 among the evaluated configurations.
