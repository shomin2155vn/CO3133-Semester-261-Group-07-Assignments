Problem statement

Food-11 recognition is a supervised image-classification task: given one food photograph, predict its single supplied category. The study asks whether ImageNet-pretrained visual features and backbone fine-tuning improve recognition over a compact network trained from scratch, and how those choices affect class-wise errors and computational cost. Macro-F1 is the primary metric because it gives equal weight to all 11 categories.

The task is defined by the following elements:

  • Prediction unit: One RGB food photograph assigned to one broad category; there are no bounding boxes, segmentation masks, or ingredient-level labels.
  • Input: A float32 tensor x ∈ ℝ3×256×256. The notebook resizes the longer image side to 256 pixels with bilinear interpolation, centers the image on a black square canvas, and applies ImageNet RGB normalization.
  • Output: Eleven logits zθ(x) ∈ ℝ11, one for each Food-11 category (Bread, Dairy product, Dessert, Egg, Fried food, Meat, Noodles-Pasta, Rice, Seafood, Soup, and Vegetable-Fruit). The predicted label is the highest-scoring class after softmax; these scores are not assumed to be calibrated probabilities.
  • Objective and primary metric: Training minimizes unweighted multiclass cross-entropy in FP32. Held-out performance is assessed primarily with test Macro-F1, alongside accuracy, per-class metrics, confusion matrices, and runtime measures.
  • Main difficulties: Food appearance varies with preparation, viewpoint, lighting, scale, and background; some categories have overlapping visual cues, composite dishes have one broad label, and the source training counts are imbalanced (up to a 5.36:1 ratio).

The frozen-versus-full ResNet-18 comparison holds the architecture and ImageNet initialization fixed while changing whether the backbone is updated. Comparisons with SimpleCNN also change architecture and initialization, so they describe overall model differences rather than isolating a causal effect of pretraining alone.

Dataset description and EDA

Dataset description

Source, task and license

Original source and version. Food-11 was released by the Multimedia Signal Processing Group (MMSPG) at EPFL and introduced by Singla, Yuan and Ebrahimi (2016) in Food/Non-Food Image Classification and Food Categorization Using Pre-Trained GoogLeNet Model. This project uses the Kaggle mirror maintained by trolukovich; the EDA notebook pins its automatic download to version 1. EPFL is the original dataset source.

Collection and category design. Section 4.2 of the original paper describes categories adapted from major USDA food groups. Images were mainly collected from Food-101, UEC-FOOD-100 and UEC-FOOD-256, with additional Flickr and Instagram images for Dairy product and Vegetable-Fruit. The authors included varied food items within each category and selected images whose main content belonged to that category.

Task and annotations. The task is supervised, single-label classification: given one RGB food photograph, predict one of 11 broad food categories. The prediction unit is one image. In the Kaggle distribution used here, labels come from class folders and are mapped to integer IDs 0–10 as listed in Table 2. A mixed dish still receives one supplied category label. The group preserves the supplied class labels and official split assignments for retained images, but applies MD5 and pHash duplicate screening and two documented manual exclusions before evaluation. The resulting splits contain 9,846 training, 3,364 validation, and 2,770 test images.

License and use. The EPFL conditions of use permit use, copying, modification and distribution of the dataset and its documentation for research purposes only and prohibit commercial distribution. This project uses Food-11 for academic coursework and research under those published conditions.

Bias and limitations

  • Classes are imbalanced, with fewer examples for Rice, Dairy product and Noodles-Pasta.
  • Each image has one label; representative sample inspection includes composite plates and images that appear off-topic.
  • Photographic style differs by class and repeated images occur across the official splits; both can affect evaluation.

Exploratory data analysis (EDA)

The EDA scans all files in the official release. File integrity and original image dimensions are audited before preprocessing. Pixel statistics are computed after longer-side resize to 512 px, with padding excluded; normalization statistics are fitted on the training split only.

Data integrity and splitting

All 16,643 files decode as RGB JPEGs; no file is empty, unreadable or inconsistent with its extension. The same 11 class folders appear in all three official splits. Of 1,887 files with a non-default EXIF orientation tag, 1,884 have the invalid value 0 and only three have a real 90° rotation; images are read as stored.

The official 59.3% / 20.6% / 20.1% training/validation/evaluation (test) split is retained. All 16,643 images are used; the group does not create a custom split or select a subset. The split unit is an individual image. No project-level random seed or stratification applies because the group does not resplit the data; the EPFL download page lists the three partitions but does not state the original split seed or whether the split was stratified.

Exact copies across the published splits mean image-level splitting does not eliminate leakage. Class proportions are similar across splits (χ² test p = 0.806; Cramér's V = 0.021).

Data preprocessing

For model input, images are decoded as stored, converted to RGB, resized with Lanczos so the longer side is 512 px and centre-padded with the rounded training mean (142, 115, 88). Values are scaled to [0, 1] and standardized with the training-only means and standard deviations in Table 7. Each image produces a float32 tensor with shape [3, 512, 512]; a batch has shape [B, 3, 512, 512]. The EDA uses no augmentation; any training-time augmentation belongs to the model-training protocol and is not assessed here.

Methodology

Pipeline overview

The classification pipeline follows a strict, end-to-end sequential workflow across all experiments on the Food-11 dataset:

Raw data → MD5 & pHash deduplication → 256×256 preprocessing → DataLoader (bs=128) → Model logits → CE loss → AdamW & ReduceLROnPlateau → Best Val Macro-F1 checkpoint → Test evaluation
  • Raw Data & Leakage Prevention: All 16,643 JPEG images across the predefined Food-11 training (9,866), validation (3,430), and evaluation/test (3,347) folders are decoded and audited before training. Exact duplicates (identical MD5 file checksums) and near-duplicates (64-bit perceptual hash Hamming distance ≤ 5, plus two visually verified duplicate pairs) are removed within each partition first and then across partitions with retention priority given to training, validation, and evaluation, leaving 2,770 deduplicated test images across all 11 classes.
  • Aspect-Preserving Preprocessing & Augmentation: Each image is converted to RGB, resized via bilinear interpolation so its longer dimension becomes 256 pixels while preserving aspect ratio, and centered on a black 256 × 256 canvas. Pixel values are scaled to [0, 1] and normalized using fixed ImageNet-1K channel statistics (mean = (0.485, 0.456, 0.406), std = (0.229, 0.224, 0.225)). Training images additionally undergo random horizontal flipping (p = 0.5) after resizing and padding, while validation and evaluation images are processed deterministically.
  • Data Loader: PyTorch DataLoader instances group tensors of shape (B, 3, 256, 256) into mini-batches of batch_size = 128 with num_workers = 0 and incomplete final batches retained. Training uses seeded shuffling (torch.Generator().manual_seed(seed)), whereas validation and evaluation loaders do not shuffle.
  • Model, Loss & Optimization: A custom 4-block convolutional network trained from scratch (SimpleCNN) and two transfer-learning variants of ResNet-18 (resnet18_frozen linear probing and resnet18_full end-to-end fine-tuning) output 11 class logits in FP32. Models minimize unweighted nn.CrossEntropyLoss using AdamW (weight_decay = 1e-2) over a fixed budget of 25 epochs with ReduceLROnPlateau stepped on validation loss.
  • Checkpoint Selection, Prediction & Evaluation: For each seed (42, 43, 44), the checkpoint with the highest validation Macro-F1 (ties broken by lower validation cross-entropy loss) is restored before final test evaluation. Logits are converted via softmax and argmax to compute overall Macro-F1, Top-1 Accuracy, Macro-Precision, Macro-Recall, test cross-entropy loss, per-class metrics, confusion matrices, and qualitative prediction diagnostics.

Comparison and discussion

Error analysis

The analysis below uses three models, seeds 42–44, and the same deduplicated set of 2,770 test images. Counts are means across seeds; ± values are sample standard deviations. Across the shared test images, the number misclassified in at least one seed / in all three seeds is 1,464 / 756 for simple_cnn, 481 / 376 for resnet18_frozen, and 334 / 154 for resnet18_full. These counts show whether mistakes recur across training runs; they do not measure confidence, and the wrong label can differ between seeds.

Similar-looking food classes are confused

Description and frequency: Some foods share visible cues, so the model can mistake one category for another. Mean errors per seed fall from 1,097 (39.60% of test images) for simple_cnn, to 426 (15.38%) for resnet18_frozen, and 239 (8.63%) for resnet18_full. Dairy product has the lowest recall for every model: 18.82 ± 2.75% for simple_cnn, 70.07 ± 1.80% for resnet18_frozen, and 80.50 ± 1.42% for resnet18_full. For the full ResNet-18, Bread is the next weakest class, with recall 85.07 ± 2.33%. The smaller CNN also confuses Rice with Noodles-Pasta: 31.0 ± 6.6 of 90 Rice images per seed are predicted as Noodles-Pasta, and 17.0 ± 8.5 errors occur in the reverse direction. The pretrained ResNet-18 models make at most one error per seed on this pair.

Examples: In resnet18_full (seed 42), Bread/57.jpg is assigned to Fried food with a score of 44.83%, only slightly above 41.53% for its true class. Golden, crisp-looking edges can plausibly resemble either bread or fried food. In seed 44, Dessert/438.jpg is assigned to Dairy product (63.16% versus 27.78% for Dessert). For simple_cnn, Rice/62.jpg (seed 42) is labelled Noodles-Pasta (45.94% versus 31.60% for Rice), while Noodles-Pasta/38.jpg (seed 44) is labelled Rice (56.29% versus 37.24% for its true class).

Hypothesized cause: In everyday terms, a small photograph may show the color or texture of a dish more strongly than the ingredients that distinguish its label. Creamy dairy and desserts can both look pale and smooth; bread, eggs, and fried food can all look golden or crisp. A mixed dish may also contain several ingredients despite having only one supplied label. Before duplicate cleaning, the source training split is imbalanced: it has 1,500 images each for Dessert and Soup, compared with 429 Dairy product and 280 Rice images. These factors could make the distinctions harder to learn, but the experiments do not isolate their effects.

Improvement ideas: Review the confused examples and add or augment images that show the distinguishing cues for under-recalled classes. Compare class-balanced sampling or loss weighting in a controlled ablation. Track Macro-F1, per-class recall, and directional confusions so that improvements to one class do not hide new errors elsewhere.

SimpleCNN often mistakes other foods for Dessert

Description and frequency: This is a repeated directional error pattern: many images whose true labels are other foods are assigned to Dessert by the from-scratch CNN. Its confusion matrices contain 317.3 ± 68.7 such predictions per seed, about 28.9% of all its errors. The largest sources are Meat (67.3 ± 30.2 images per seed), Dairy product (58.0 ± 15.1), Egg (47.3 ± 14.6), and Soup (41.7 ± 17.2). This pattern occurs in all three seeds; resnet18_full has about 55 false Dessert predictions per seed.

Examples: In the qualitative examples, Dairy product/101.jpg (seed 42) is assigned to Dessert (27.92% versus 14.59% for Dairy product), and Meat/194.jpg (seed 43) is assigned to Dessert (31.56% versus 22.92% for Meat). These examples show the direction of the mistakes, not high confidence. The first image places cheese, crackers, and fruit together, so several food cues appear in one frame.

Hypothesized cause: A small network trained from scratch may rely on broad cues such as color, texture, or plating instead of learning features that separate each category reliably. Dessert is also one of the largest source training classes. When a dish is ambiguous, those factors could make Dessert an attractive guess for several other classes. The matrices establish the repeated bias, but they do not prove that class frequency caused it.

Improvement ideas: Inspect false Dessert predictions by their true class, then test class-balanced sampling or a weighted loss. Add targeted examples or augmentations for Meat, Dairy product, Egg, and Soup. Check whether Dessert precision improves while recall in the smaller classes is preserved.

Wrong predictions with high softmax scores

Description and frequency: This asks a different question: not which classes the model confuses, but how high a score it gives a wrong answer. The notebook defines this as a top-1 softmax score of at least 0.80. There are, on average, 35.0 such errors per seed for simple_cnn, 55.7 for resnet18_frozen, and 124.7 for resnet18_full—about 3.2%, 13.1%, and 52.2% of each model's errors, respectively. In an app, this could look like a confident answer to a user even when the food label is wrong.

Examples: In resnet18_full (seed 42), Dessert/60.jpg is predicted as Seafood at 98.75%, while Dessert receives 0.72%; Dairy product/113.jpg is predicted as Dessert at 98.22%, while its true class receives 0.37%. In the frozen model, Egg/11.jpg (seed 42) is predicted as Dessert at 93.32%, while Egg receives 4.05%. The piped filling and garnish on this egg dish can resemble dessert decoration. By contrast, the strawberry dessert predicted as Seafood is not an obvious visual match to a person.

Hypothesized cause: The model does not understand the dish as a person would. It combines visual cues it learned during training; when those cues strongly match the wrong class, it can produce a very high score. Visual similarity may explain some cases, while background, color, unusual composition, or an ambiguous supplied label may explain others. The notebook has no attribution map for these specific images, so the exact cue cannot be confirmed. A high softmax score by itself also does not prove systematic miscalibration.

Improvement ideas: Check reliability diagrams, expected calibration error, and Brier score. Fit temperature scaling on validation data and assess it on the held-out test set. Test label smoothing or Mixup as training ablations. If this model is used in an app, calibrated uncertainty and a human-review option could help prevent a wrong answer from being silently accepted.
